# Responsible AI note

> **All data behind this document is synthetic and the system is not validated on real data.**
> Simulated money, sandbox prototype, not a product of upay or any other company.
> Generated by `scripts/build_docs.py` from `reports/*.json`; do not edit by hand.

**Privacy.** The prototype holds no personal data: names are generated, wallet numbers carry a
`SIM-` prefix, money is simulated. Only the minimum a dispute needs is stored (claim text,
evidence text, timestamps). Hidden fields (ground-truth archetype, internal scores of limited-history
sellers) are excluded from API responses (tested). Evidence text is shown escaped. There is no
sign-in in the sandbox; a real deployment would need authentication, access control and a data
protection review that this prototype does not provide.

**Explainability.** Every Trust Check shows two to four reasons and every analyst case shows a
timeline, flags, class probabilities and a written explanation built from fixed bilingual
templates. No generative model is anywhere in the decision path.

**Fairness.** New sellers are not scammers. Sellers with little history get a neutral
LIMITED_HISTORY band instead of a score. Literally applying the blueprint rule hides the high-risk
fakes too (recall of high-risk sellers 54.3% on the test data); the configured policy keeps
them visible (recall 97.7%) while honest new sellers wrongly flagged are
1.0%. That threshold is a
policy choice for humans to confirm. No demographic fairness check is possible with synthetic data.

**Security.** Dispute text is untrusted input. A screen removes instruction-like sentences before
the classifier and rules see them and forces human review when one is found. The pattern screen caught 1 of 12 injection phrases written after it was built (and all of those it was built on): it is a first filter, not a defence.
The real protection is structural: no free text can change a label, a route or a ledger entry, the
ledger is double-entry and append-only (database triggers), and every state change is audited.
Inputs have length limits and are validated.

**Human oversight.** The analyzer only *suggests*. A person decides every dispute, must write a
note, and confirms any money movement. Low confidence, high amounts, any flag, or insufficient
evidence send a case to a human; the fast lane only pre-fills a confirm button and is never automatic.
Seller trust scores update only after a human decision.

**Limits to state out loud.** Everything is synthetic and not validated on real data; the Bangla
text was drafted by an AI assistant and needs review by a native speaker; holding customer funds
may need regulatory approval, so Safe Order is shown as a future feature governed by the payment
provider, simulated here.
