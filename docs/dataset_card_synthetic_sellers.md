# Dataset card: synthetic seller data (generator v1 and v2)

> **All data behind this document is synthetic and the system is not validated on real data.**
> Simulated money, sandbox prototype, not a product of upay or any other company.
> Generated by `scripts/build_docs.py` from `reports/*.json`; do not edit by hand.

## What it is

Sellers, buyers, orders and daily statistics produced by `scripts/generate_sellers.py` from the
parameters in `config/config.yaml`. Names are "Synthetic Shop NNNN", wallet numbers start with
`SIM-W-`. **There is no real person, seller, wallet or transaction in it.** Every parameter is an
assumption, listed in full in `synthetic_assumptions.md`.

| | v1 (training) | v2 (test) |
|---|---|---|
| Seed | 1001 | 2002 |
| Sellers | 3,000 | 3,000 |
| Orders | 305,206 | 258,826 |
| Share labelled high-risk (`is_high_risk`) | 27.7% | 25.3% |
| Label noise realised | 4.7% | 3.7% |

v2 shifts the archetype parameters by about +/-20% and uses a different archetype mix, so a model
that memorised v1 loses points on v2.

## Labels

`is_high_risk` is 1 for the three fraud archetypes (`fake_burst`, `slow_scammer`,
`collusive_ring`) with a random flip of about 4%. `chronic_poor_service`
sellers are deliberately **not** labelled high-risk: poor service is not fraud.

## Known limitations

- It encodes our own assumptions about how fake sellers behave; the model is graded on whether it
  finds them again. That is a test of the pipeline, not of reality.
- The fraud archetypes are cleanly separable by design, apart from the label noise and an
  intentional overlap with honest new sellers. Real data would be messier.
- No language, region or demographic attributes exist, so no demographic fairness check is possible.
- Daily statistics cover 60-90 days before
  2026-10-01.
